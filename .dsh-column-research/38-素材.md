> 素材包，写于 2026-10-11。路径与行号相对 `local/deepseek-harness-dsh-v0.2.0-rc.2/`（本栏当前基准快照）。

> 对应正文：`38-会话格式升级了.md`；demo：`code/dsh_plugin/dsh-session-audit/`。

## 1. 磁盘布局

- 会话根：`$DSH_HOME/sessions`（base bundle 的 `session-persistence-jsonl` 配 `root: !!js dshHomePath('sessions')`；`$DSH_HOME` 默认 `~/.dsh`）。
- 层次：`<root>/<normalized-cwd 或 _no-cwd>/<encoded-id>/session[.vN].jsonl[.zstd]`，外加 `session.lock`（POSIX `flock` 写租约）。
- **一个会话一个目录，每个已发布的格式世代一个文件，全部保留**；运行时选数值最高的那一代。
- 文件名正则（`packages/session/session-format/src/filename.ts:5`）：`/^session(?:\.v([1-9][0-9]*))?\.jsonl$/u`；v0 = `session.jsonl`，vN≥1 = `session.vN.jsonl`（小写、无前导零、无 `.v0`）。临时名/大写/带压缩后缀都不是规范名。
- 压缩默认 `zstd`（`compression` 可配）；`.zstd` 是后端在规范名之后追加的。
- 每个规范文件首行是物理头（`session-persistence-jsonl/src/format.ts:83-94`）：`type`、`version`、`id`、`createdAt`、`cwd?`、`parentSession?`、`isSeeded`、`origin?`、`delegationDepth`、`agentPreset?`。**文件名里的 N 必须等于首行 `version`。**
- 已退休头字段（`sandboxMode` / `approvalPolicy`）→ 拒读（`assertNoRetiredHeaderFields`）；这种结构性拒绝**不被当作可恢复尾部**，即使更早处已有损坏行。

## 2. 三个版本号

| 名字 | 值 | 权威 |
| --- | --- | --- |
| 写入器 | 4 | `SESSION_FORMAT_VERSION`（`packages/core/session/src/types.ts:89`） |
| 已定稿 | 4 | `docs/session-format-status.md:31-33`（`finalized/v4.json`） |
| 已发布 | 3 | `docs/session-format-status.md:44-49`（`evidenceTag: dsh-v0.1.5-alpha.1`） |

- 逻辑头 `version` 恒为写入器版本；历史物理头在进入 `SessionHeader` 前已被翻译。
- **alpha / beta / rc 发布同样建立格式义务**（`session-format-status.md:24`）；prerelease 标记不使数据可丢弃。
- 冒充者：包版本、codec 导出名、夹具文件名、投影缓存 `stateVersion`——都不是格式权威。

## 3. 迁移链

- 边必须**相邻**：`defineSessionFormatMigration` 校验 `to === from + 1`，否则抛 `must declare adjacent v${from}->v${from + 1}`（`session-format/src/chain.ts:24-34`）。
- 边在**构建期固定**：生成器读各迁移包 `package.json` 的 `dsh.sessionFormatMigration` 元数据，产出 `session-format-catalog/src/generated.ts`（`currentVersion: 4`、codecs v0..v4、migrations v0→1..v3→4）。README 原话：profile 不能加/删/重排边。
- 链构造：从 0 逐级取边，缺级抛 `Session migration vN->vN+1 is missing`；多余边也抛。
- 计划与执行分离：`plan(fromVersion)` / `createStream`（逐级 stage）/ `migrateHeader`（仅头）。
- 每级做了什么：
  - 0→1：头归一 + 有限历史规范化（`compact/*` → `compaction/*`）。
  - 1→2：`assistant/chunk` 内嵌进 `assistant/message`；无消息的尝试记 `assistant/attempt`；序号密集重映射。
  - 2→3：system prompt 提升为 `system/message`；重映射本地引用；预设名 `code` → `ptc`；envelope 规范化。
  - 3→4：头版本推进；tool result 提升为 tool-role 消息、重命名消息来源、关闭有证据的中断轮次、补齐父会话缺失的 `subagent/catalog`。
- **3→4 的 body 迁移要求显式子会话证据**，没有子会话也要空数组，否则抛 `V3 catalog migration requires explicit historical child facts, including an empty array for a parent without children`。

## 4. 打不开的情况（fail-closed）

| 条件 | 结果 |
| --- | --- |
| 存储头版本 > 写入器 | `unsupported` + 带绝对路径的拒绝诊断 |
| 头非 JSON 对象 / 版本非非负安全整数 | `malformed` |
| 该版本无 codec | `unsupported` |
| 缺迁移边 | 构造期抛 |
| stage 拒绝 artifact | `<边名> refuses this format vN Session: <detail>` |
| 迁移结果过不了当前校验 | `refuses the transformed artifact: …` |

- 用户侧 `SessionFormatUnsupportedError`：`The stored log is intact but this runtime cannot faithfully interpret it.`
- 方向敏感文案（`session-persistence/src/errors.ts:123-137`）：更新 → "upgrade the harness to open it"；更旧 → "ships no upgrade path"。
- **无回退、无降级**：最高世代拒绝时，旁边有可读旧世代也不兜底（`docs/subsystems/persistence.md:189`）。
- `SessionLocation.path` 只出现在拒绝诊断里，不是消费者查询入口。

## 5. 没有备份文件

- **读打开从不发布**：解码 → 迁移 → 校验当前逻辑结果 → 返回，源文件一个字节不动。
- **写打开**才发布"当前后继"，且独占新建（同目录临时文件 → Worker 校验 → 重查源 revision → `link` 发布；`EEXIST` 视为已有后继，**永不覆盖**）。
- 因此"备份"= 前代文件还在；没有 `.bak`。
- 崩溃语义：不完整末行丢弃；撕裂的 zstd 末帧只贡献完整记录；已完整提交帧校验/解压/结构失败 → 判损坏拒读。

## 6. 入口

- 没有 `dsh doctor` / `dsh migrate` / `dsh repair`（CLI 只有启动器 flag 与 `plugin` 子命令）。
- 一次性脚本：`pnpm run migrate:sessions-to-v4 [--sessions-dir PATH] [--jobs N]`（默认 `~/.dsh/sessions`；已 V4 的只读打开；单个失败不阻断；日志与 JSON 摘要落私有临时目录）。
- `pnpm run verify-v3-event-vocabulary --source-ref <commit>`：V4 首发前的 V3 词汇核对。

## 8. 读会话的正规面

| 用途 | API |
| --- | --- |
| 列/读/过滤/导出 | `ctx.sessionQuery` |
| 存在性与大小（不读 body） | `ctx.sessionPersistence.stat(id)` / `list()` |
| 派生状态 | `ctx.sessionProjections` |
| 判磁盘世代 | `parseSessionFormatLogFilename()`（`dsh-session-format`） |

- `stat` / `list` 返回 `SessionPersistenceSnapshot`：`header`（逻辑头，版本恒为写入器）、`revision`、可选 `eventCount` / `sizeBytes`。
- **公开 API 不暴露磁盘上的存储世代号**——这是 demo 要自己扫文件名的原因（也是写作时确认的真实缺口）。
- 反面做法：硬编码 `session.jsonl`；自己逐行 `JSON.parse`（默认 zstd 帧拼接，只有配 `compression: 'none'` 的根可行读，同根只允许一种编码）；绕过 catalog 自建适配层（会漏拒读规则：未知必需事件拒、退休字段拒、v0/v1/v2 对未知类型即使 `ignorable` 也拒）；按 `session.header.version` 写分支（恒为写入器版本）。

## 9. demo 落点

`code/dsh_plugin/dsh-session-audit/`：扫会话根判物理世代 + `ctx.sessionPersistence.list()` 取逻辑头，输出"写入器版本 / 磁盘会话数 / 需迁移数 / 需更新 harness 数 / 正规 API 会话数"。**只读**：不 `open('write')`、不 publish、不迁移。走 `patch.yaml` + 插件行直接指 `src/index.ts`。
