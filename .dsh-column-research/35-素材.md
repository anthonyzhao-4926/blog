## 1. commands

### 服务面（`packages/interaction/commands/src/index.ts`）

| 方法 | 签名要点 |
| --- | --- |
| `register(definition)` | 返回**精确的 effect disposer**；内部已挂到调用方 effect 上（`this.layers.effect(...)`），外面不必再包 `ctx.effect` |
| `registerFileReceiptResolver(resolver)` | 全局唯一；注册第二个抛 `commands: a file receipt resolver is already registered` |
| `list(agent)` | `@Remote`，返回按名排序的 `CommandDescriptor[]`（无 handler） |
| `find(agent, name)` | **非 Remote**，只在同进程可用 |
| `execute(agent, line, attachments, signal)` | `@Remote`；唯一执行入口，返回 `CommandExecution \| undefined` |

`CommandDefinition` 字段：`definitionId?`、`name`、`description`、`input?`、`recordInput?`、`handler`。
`CommandInputDescriptor`：`hint: string`、`attachments?: boolean`。
`CommandResult`：`{ kind: 'success'; text?; sourceEventSeq? }` \| `{ kind: 'error'; text }`。
`CommandInvocation`：`commandId`、`agent`、`rawInput`、`attachments`、`signal`。
`CommandSubmitAttachment`：`{ type: 'image' } & EncodedImageAttachment` \| `{ type: 'file'; receiptId }`。
brand：`CommandDefinitionId` / `CommandId` 都是 `Branded<...>`，运行时就是普通字符串（`brand.ts` 的构造函数）。

### 解析与语法

- 语法正则：`/^\/([a-z][a-z0-9_-]*)(?=$|[\t\n\r ])/u`（`index.ts:126`）。
- 注册期校验：`COMMAND_NAME = /^[a-z][a-z0-9_-]*$/u`。
- `rawInput = line.slice(match[0].length)`，**包含分隔空白**；没有参数解析。
- 没有别名（中文 token 只覆盖六个一方命令，靠 `definitionId` 认身份）；不支持大写。

### 重名与作用域

- 同层重复注册 → 抛错（报错文案会指路"挂到 `agent.ctx` 下"）。
- agent 作用域注册遮蔽全局 → 静默生效（`ScopedLayers.merge`，最近者胜）。
- 客户端 contribution 与 host 命令同名 → 合成候选项时抛错。

### 事件与生命周期

```ts
'command/run':  { commandId, name, args?, source }      // recordInput: false 时没有 args
'command/done': { commandId, kind: 'success' | 'error', text?, sourceEventSeq? }
```

- 写序：mint `commandId` → 追加 `command/run` → 跑 handler → 追加 `command/done`。
- **准入失败（语法/未知命令）什么都不写**，直接返回 `undefined`。
- 附件准入失败仍然写 `run` + `done(error)`（`command/run` 在准入之前追加）。
- 两条都是 log-only、无 turn 包裹、不进模型（Model Experience：0 token）。
- 不变式：同日志内按 `commandId` 配对；`sourceEventSeq` 只允许 success、必须指向更早的非 command 事件。

### 谁执行

- 出厂唯一 adapter 是 **Web 客户端**（`packages/client/ui-commands/`）：按 session 缓存目录、`ctx.remote.$on('commands/change')` 后 `invalidateAll()`。
- 包 README 与一条 Agent Note 仍写"只有 TUI 消费"，**快照里没有 TUI 包**（`find -type d -name '*tui*'` 为空）——以快照为准。
- 装配：`base` 挂 `commands`；`sdk-minimal` 无该行；`headless`/`sdk`/`acp` 挂注册表但没有 adapter。

### 让模型看见

handler 必须自己投递。出厂 `/plan`（`packages/plan/plan-mode/src/index.ts:230-284`）是模板：

```ts
input: { hint: '[off|message]', attachments: true },
handler: ({ agent, rawInput, attachments }) => {
  ...
  agent.steer(createUserMessage({ content: [...attachments, ...], source: { kind: 'user' } }))
}
```

三个投递动词（`packages/core/agent/src/runtime-types.ts:215-246`）：`followup()` 排一整轮、`steer()` 交给最近一步（空闲会开一轮）、`inject()` 只给下一个 pre-step 且不唤醒（可能错过已认领批次的请求）。

## 2. attachment

### 身份

- `AttachmentId` = `Branded<'AttachmentId'>`；本地后端当前发 `sha256:<digest>`，但**消费方不许解析、不许据此推路径**（`docs/subsystems/attachment.md:13`）。
- `ImageAttachmentRef`：`attachmentId`、`mediaType`（`image/png|jpeg|webp|gif`）、`bytes`、`width`、`height`、`name?`、`originalDimensions?`。
- `FileAttachmentRef`：`attachmentId`、`name`、`bytes`。

### 时序与验证读

- **先落盘后发事件**：Host 接受 user message 之后、追加 user 事件之前，图片移到 `<DSH_HOME>/attachments/v1`；模型侧图片输出同理。日志里只有引用与元数据。
- `readImage(ref, signal?)`：读一张图并**重验**摘要、媒体签名、尺寸、元数据（`docs/subsystems/attachment.md:236-243`）。
- `imageHostPath(ref)`：只给 provider 自己的宿主路径；能否被读由**当前执行世界**的文件系统裁决。
- 浏览器取图要两道：先证明该 session 日志引用过这个 id（`referencedImage()`），再 `readImage`。

### 存储 seam

| 角色 | 包 |
| --- | --- |
| 服务定义 | `dsh-attachment`（抽象类 `AttachmentStore`，`ctx.attachments`） |
| 提供方 | `dsh-attachment-local`（落 `<DSH_HOME>/attachments/v1/...`，**不经过 storage domain**） |
| 消费者 | `dsh-tool-fs` 的 `read_image`、`llm-deepseek`、`api-session-controller` |

- 同一 scope 不能并存两个 provider（Cordis `provide` 同名抛错）；换后端要替换那一行或进 isolate realm。
- 抽象类未实现的方法有默认拒绝（`ATTACHMENT_FILES_UNSUPPORTED` / `ATTACHMENT_PROJECTION_UNSUPPORTED`）。
- 限额：20 张/条、单张 20 MiB、单条 200 MiB、单张 6400 万像素、单边 8192；归一化长边 2048、编码 4 MiB。
- `read_image` 额外要求**当前路由的模型声明 image 输入**（`assertImageCapableRoute`）。

## 3. 命令带附件

- executor 强制准入：未声明 `input.attachments`、无附件存储、回执未知、批次超限 → handler 之前 error。
- 通过后 handler 拿到冻结的 `invocation.attachments`（`ImageBlock | FileBlock`），顺序为提交顺序；**模型可见与否由 handler 决定**。

## 4. feedback

| | 会话级 | 消息级 |
| --- | --- | --- |
| 入口 | `/feedback <text>`（`recordInput: false`） | Web 界面评分/加注 |
| 服务 | `ctx.sessionFeedback.record()` | `ctx.messageFeedback` 的 `list`/`put`/`delete` |
| 事件 | `feedback/record` | `feedback/message-put` / `feedback/message-delete` |

- 两类都**不进模型历史**；遥测默认 `FEEDBACK_ONLY`，判定依据就是这些事件。
- 消息级是严格乐观并发（no-op 也要带对 `ifVersion`）；目标仅限 append-origin 的 `assistant/message`。

## 5. deliverables

- `present`（`dsh-tool-present`）：`files[{ path, description? }]`；校验存在/普通文件/open turn/cwd；在 `tools/result` 上确认成功才追加 `deliverables/presented { turn, callId, files }`。`maxFiles` 默认 8，参数描述里的"最多 4"是推荐值（源码注释写明）。
- `dsh-workspace-changes`：监听 `session/event` 折 `workspace/changes { turn }`；summary/diff 由 Host 服务内存提供，会话释放或 Host 重启即失。
- 两者都只给客户端读（`ui-deliverables`）。
