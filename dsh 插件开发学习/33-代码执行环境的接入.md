上一篇讲的是"给模型立规矩"，这一篇讲"给它动手的地方"。

模型写一段代码、跑一下、看结果——听起来简单，但接的时候有几个决定要提前定清楚：**失败怎么报**、**它能看见什么**、**跑在哪儿**。这几条定错了，模型就没法从错误里恢复。

## 目标

- 分清代码执行这套东西里"请求"和"实现配置"的边界。
- 知道六个失败分类为什么必须分开。
- 理解绑定命名空间的作用与风险。
- 知道子进程那条缝上环境变量的归属规则。

## 一条可选的缝

代码执行是一个标准的能力 seam：**Service Definition 用宿主提供的异步绑定，运行一段模型编写的程序，报告它的打印内容与返回值。**

有一句话要留意：**代码执行是可选的，不属于 agent loop 主干。** 这就是为什么它的词汇定义在子系统页而不是 `core.md` 里——主干上的东西不能是可选的。

一次运行的请求：

```ts
interface CodeRunRequest {
  program: string
  bindings: CodeBindingNamespace[]
  signal?: AbortSignal
}
```

三个字段，但第一个字段的注释里藏着一个约定：

> 按照「包边界处显式优于隐式」的规则，**默认值（时间预算、输出上限）来自实现的已校验配置，绝不是 `run()` 内部隐藏的 `??`。**

这句话的实践含义是：**要调预算，就去改那一行的配置，而不是指望在请求里传一个可选参数**。请求里根本没有那些旋钮——因为一个藏在实现里的 `??` 默认值，是那种"读代码才发现"的东西。

`program` 会**作为 async 函数的函数体运行**，所以顶层 `await` 和 `return` 都能用，而完成值会成为结果的 `value`。

## 绑定：宿主函数作为程序全局变量

`bindings` 是把宿主能力交给程序的方式：

```ts
interface CodeBindingNamespace {
  namespace: string
  functions: Record<string, (...args: unknown[]) => Promise<unknown>>
}
```

**一个命名空间一个全局对象。** 也就是说你声明 `namespace: 'lab'`、里面有个 `upper` 函数，程序里就能直接写 `lab.upper('x')`。

这里有两个判断要做对：

**给多宽？** demo 里只给了两个函数。把整个 `ctx` 递进去的那种做法很方便，但它等于把插件的全部能力（包括注册、销毁、访问服务）暴露给一段模型写的代码。

**异步。** 绑定函数的签名是返回 Promise 的，所以程序里调它们得 `await`。

还有一个容易漏的约定，写在 `signal` 的注释里：

> **in-flight 的绑定调用是调用方自己的事——runtime 只是不再问了。**

也就是中止时，runtime 会硬停下那段程序（**即使在循环中间**），但**已经在执行中的绑定调用不会被它收回**。那些调用的结算归调用方。如果你写的绑定是"发一个网络请求"，那它得自己处理中止。

## 失败是字段，不是异常

这是这套接口里最该记住的一条。

`run()` **不会返回被拒绝的 Promise**。它总是正常兑现，把错误放在结果里的一个字段上。

理由和 shell 执行器那条约定一致：**报告程序失败是调用方的职责，不走异常路径。**

这两条路带来完全不同的写法。用异常的话，调用方要 `try/catch`，而 catch 到的东西和"程序自己抛的异常"混在一起——你分不清"这段代码写错了"和"这段代码里真的 throw 了"。用字段的话，这两件事天然分得开（后者是 `kind: 'exception'`）。

## 六个失败分类

失败类型是**正交的结果、独立报告**的：

```ts
interface CodeRunFailure {
  kind: 'exception' | 'timeout' | 'abort' | 'worker-exit' | 'invalid-output' | 'output-limit'
  message: string
}
```

原文对"正交"的解释值得原样抄一遍：

> 预算耗尽不是异常，中止不是超时，基底崩溃（如 OOM）也不是二者中的任何一个。

逐个看这六个，能看出它们对应的是**六种不同的自救方式**：

| kind | 什么情况 | 模型该做什么 |
| --- | --- | --- |
| `exception` | 程序抛出，或解析/转换失败 | 改代码 |
| `timeout` | 实现自己的预算到期 | 缩短任务、别写死循环 |
| `abort` | 请求的 `signal` 触发了 | 这是被叫停的，不是它的错 |
| `worker-exit` | 执行基底死了（如 OOM） | 少占内存，或任务本身太大 |
| `invalid-output` | 完成值不是无损 JSON | 返回值改成可序列化的 |
| `output-limit` | 序列化的日志/值/诊断超过上限 | 少打印点东西 |

如果这六种被压成一个"运行失败了"，模型能做的只有瞎猜。分开了，它至少知道**是改代码、还是改任务规模、还是别打印那么多**。`message` 的定位也写在注释里：**适合喂回给模型让它自我修正**。

## 输出与上限

关于捕获的输出，有几条实现层面的约定：

- **日志是纯字符串。** 每个来源通道保留自身的发出顺序；但**通道元数据不属于这条缝**，所以相互独立的通道之间怎么交错由后端决定——别依赖两个通道之间的相对顺序。
- **上限作用在"可变载荷"上**：序列化后的外层日志数组，加上完成值或失败消息的组合载荷。**固定的结果封装语法与 Consumer 展示空白不计入这份计量**——也就是说你不用担心格式化开销吃掉了你的预算。
- **超限会显式失败**（`output-limit`），**而不会在值里插入替代内容**。这一点和 21 篇里"截断要说清楚"是同一种态度：悄悄塞个 `...` 进去，模型会以为那就是全部。
- 每条被收集的流通过 `CollectedOutput` 报告自身的**截断与恢复状态**：`text` 在截断时是**流的尾部**，`truncated` 标明有没有丢字节，另外还有一个**装着完整流的文件**（截断且可用时）。

## 两个只读描述符

服务上还有两个描述符，是给消费者做展示用的：

- **`language`**：程序必须使用的语言。已知值是 `'typescript'` 和 `'python'`——**TypeScript 后端已发布，Python 后端为实验性且私有（未发布）**。生成语言相关展示的消费者要据此切换；**遇到自己无法展示的语言时应显式报错**，而不是硬渲染。
- **`isolation`**：执行基底，取值 `'worker-thread'` / `'process'` / `'container'`。这个字段有个必须点明的限制——它是**仅为诊断标签，不构成安全承诺**。别看着 `container` 就以为得到了沙箱隔离的保证；安全边界是 21 篇讲的那三层（沙箱、观察策略、权限预设）在管。

另外两条实现在自身上的约束：**各次运行必须彼此隔离（无跨运行状态）**；**dispose 时要等系统完全停稳**——teardown 会等到所有进行中的运行都已经终止并结算才完成。

## 子进程

代码执行是一条缝，子进程是另一条，两者常一起用。

子进程 seam 的消费者**不是插件，而是其他能力 seam 与进程外后端**：bash 执行器家族用收集模式的批量输出、LSP 用原始协议管道、PTY 后端用终端原语、ACP subagent 后端用管道传输的 ndjson 并让 stderr 走 inherit。所以它是**底座**，不是给模型直接用的工具。

它拥有三样东西，其中第一样最容易被忽略：

**受管的 `DSH_*` 环境命名空间。** 规则是：实现会在**合并调用方显式 `env` 之前，丢弃环境中已有的 `DSH_*` 名称**。所以当前事实**只会以有意提供的字符串条目形式到达**子进程。反过来，**显式的 `undefined` tombstone 会删除普通环境中已有的值**——这是一条正经的"删除环境变量"的路子，而不是"给个空字符串"。

**共享的凭据清除**（`scrubbedParentEnv`）。父进程的环境不会原封不动传下去。

**`CollectedOutput` 形状**，和上面说的那套一致。

可执行文件的查找走 `resolveExecutable(command, env?, signal?)`：**要么是验证过的绝对路径，要么通过提供方清理后的 `PATH` 加有意覆盖来解析裸名称**。

还有一句描述值得记住，它解释了"显式 spawn"这个说法的由来：**一个提供方的 spawn 工作目录、可执行文件路径、普通进程与终端会话，和挂载的文件系统提供方处于同一路径与进程命名空间**。也就是说子进程看到的世界和你挂的文件系统是同一套坐标——这是它能被权限与沙箱策略有效约束的前提。

## 跑一段代码

demo `dsh-code-lab` 的核心就是一次运行加上对结果的正确处理：

```ts
const result = await ctx.codeRuntime.run({
    program,
    // 绑定 = 暴露给这段程序的全局变量，一个命名空间一个全局对象。
    // 只暴露该给的，别把整个 ctx 递进去。
    bindings: [{
        namespace: 'lab',
        functions: {
            now: async () => new Date().toISOString(),
            upper: async (text: string) => text.toUpperCase(),
        },
    }],
    signal: exec.signal,
})
```

注意**没有 `try/catch`**——因为失败不会走出异常路径：

```ts
// 失败是字段，不是异常——所以这里不需要 try/catch。
if (result.failure !== undefined) {
    // 每个分类都值得原样告诉模型：它据此知道下一步该改什么。
    return `运行失败（${result.failure.kind}）：${result.failure.message}`
}
```

那行 `return` 里把 `kind` 和 `message` 都带上，是因为**这两样都是给模型自我修正用的**。只报一句"运行失败"等于把它能用的信息全丢了。

最后把两个描述符一并报出去，便于排查"为什么这段在别的机器上跑不了"：

```ts
return JSON.stringify({
    打印输出: printed,
    返回值: result.value ?? null,
    // 基底与语言是服务上的只读描述符，报出来便于排查「为什么这段跑不了」。
    语言: ctx.codeRuntime.language,
    执行基底: ctx.codeRuntime.isolation,
}, null, 2)
```

## 验证

```bash
cd code/dsh_plugin/dsh-code-lab && ./install.sh
```

四步，后两步是重点：

```bash
# 1. 装配对不对（三行：服务定义、工作线程提供方、我们的工具）
dsh --profile test --dump-config | grep -A3 'id: code-lab'

# 2. 跑一段正常的
dsh --profile test "用 run_snippet 算一下 1 到 100 的和，把返回值打印出来"

# 3. 跑一段会抛异常的
dsh --profile test "用 run_snippet 运行 throw new Error('boom')"

# 4. 跑一段死循环
dsh --profile test "用 run_snippet 运行 while (true) {}"
```

第三步应当返回 `运行失败（exception）`，第四步返回 `运行失败（timeout）`。

**这两个必须不一样。** 如果它们都变成一句"运行失败了"，模型就没有任何线索去区分"我代码写错了"和"这个任务太大"——而这两种情况的下一步动作完全不同。

## 注意事项

- **预算与上限在配置里，不在请求里。** 请求里没有隐藏的可选旋钮——这是刻意的"显式优于隐式"。要调就去改那一行的配置。
- **失败是字段，不是异常。** `run()` 总是不被拒绝地兑现。用 `try/catch` 去接它反而会盖住真正的异常。
- **别把六个分类压成一个。** 它们的价值就在于各自指向不同的自救方式。转发给模型时要带上 `kind` 与 `message`。
- **`signal` 是硬停止，但不收回进行中的绑定调用。** 那些调用的结算归调用方。写绑定函数时要自己处理中止。
- **绑定给多宽是个安全决定。** 一个命名空间一个全局对象，递进去的东西模型都能直接用。别把整个 `ctx` 递进去。
- **`isolation` 不是安全承诺。** 它只是诊断标签。真正的边界在沙箱、观察策略与权限预设那三层。
- **超限会显式失败，不会静默替代。** 这是好事：静默插入的省略号会让模型以为那就是全部内容。
- **别依赖不同输出通道之间的相对顺序。** 每个通道内部有序，通道之间的交错由后端决定。
- **`DSH_*` 归 Harness 所有。** 调用方提供的同名变量会被丢弃；要删一个继承来的普通环境变量，用显式的 `undefined` tombstone，而不是空字符串。
- **Python 后端还没发布。** 已知语言值里有它，但当前只有 TypeScript 后端可用；写展示逻辑时遇到不认得的语言要显式报错。
