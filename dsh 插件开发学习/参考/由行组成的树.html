由行组成的树

树是叠出来的结果，行是清单里按 id 寻址的一条记录。 左栏是四层 cordis.patch.yml 里的声明（一层一层往下叠），右栏是叠完之后长成的插件树。 树上每个节点就是一个 id；group: true 的那一行，它的 config 本身就是一份子行列表——行在这里长出枝。

叠加到第几层：
清单 · 行（按层叠放的补丁）
结果 · 树（叠出来的插件树）
把鼠标移到左边任意一行、或右边任意节点上：同一 id 的所有行会一起亮起，这里显示它在各层里被哪几行改过。
    1. 「树」说的是形态：各层叠完之后，插件之间是挂载/嵌套关系，所以产物是一棵树。
    2. 「行」说的是清单的书写与寻址单位：补丁不按树的路径定位节点，只按 id。实现上是把所有条目（含嵌套 group 的子条目）递归摊平成一张 Map<id, entry>，补丁就是往这张表里加一条、覆盖某条、或把某条停用。
    3. 三种动作：插一行 = insert 一条新条目；改一行的参数 = 按 id 覆盖该条字段（config 整体替换，不合并）；停用一行 = 该条 disabled: true。
    4. 同一节点可由多层多行改写，后写的赢（last write wins per row）。所以树上的 1 个节点，清单里可能对应 2 条以上的行——tool-fs 就是「L1 插入 + L2 停用」两条。
    5. 行的先后无语义：激活顺序由服务可用性驱动，不由行的排列决定。

    数据来源：packages/bundle/base/cordis.patch.yml、packages/bundle/web-app/cordis.patch.yml、 ~/.dsh/profiles/web/cordis.patch.yml、apps/cli/config/examples/github-review/cordis.yml （id / name / 字段取值均取自这些真实文件，节点在树上的排布作了归并）。
