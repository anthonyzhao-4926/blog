> 本文是知识卡，不用顺序读。给插件加设置项、或者在浏览器半里读写它时来查。

对应源码：`packages/settings/settings/src/index.ts`（Host 侧服务）、`packages/client/ui-settings/src/client/settings-scope.ts`（浏览器侧 scope）、`packages/client/ui-settings-plugins/src/client/slot-contract.ts`（槽位声明）。

## Host 侧：installSection

```ts
installSection<const Namespace extends string, T>(
    owner: Context,
    ns: Namespace & SettingsNamespaceInput<Namespace>,
    schema: z<T>,
    entry: T,
    hooks: SettingsSectionHooks<T>,
): void
```

| 参数 | 作用 |
| --- | --- |
| `owner` | 谁拥有这份设置。传插件自己的 `ctx`；注册挂在这个 fiber 上，fiber 卸载即注销 |
| `ns` | namespace 名，见下节命名约束 |
| `schema` | 解析这份配置的 Schemastery schema，`.default(...)` 是最底层默认值 |
| `entry` | 注册时的 base 层，通常就是 Loader 合成后交给 `apply` 的那份 `config` |
| `hooks` | 三个回调，见下表 |

`hooks` 契约：

| 回调 | 时机 | 要做什么 |
| --- | --- | --- |
| `setSource(current: () => T)` | 挂上时、以及 provider 消失时各一次 | 把传进来的取值函数存下来（例如 `let source = () => config`），之后每次用配置都调它 |
| `onChange()` | 挂上时一次；之后每次解析出的值变了、或失去 provider 一次 | 重建你手里的派生状态（缓存、注册表）。每次用到时现读的插件，空实现即可 |
| `validate?(value: T)` | 每次写入解析出候选值之后、落盘之前 | 抛错就拒绝这次写入，用于 schema 表达不了的跨字段约束 |

要点：

- `setSource` 给的是**取值函数**，不是「稳定引用」。插件自己保管它。
- 失去 provider 时框架把 source 换回组合 base，并再调一次 `onChange()`。所以插件在 provider 缺席时仍然按组合配置跑。
- 只注册一次同一个 namespace；重复注册抛 `settings namespace "x" is already registered`。
- `register` 的 `applies` 默认 `'live'`（可选 `'restart'`），作为元信息随描述一起给到界面。

## namespace 命名

- 形如 `^[a-z][a-z0-9-]*$`：小写字母开头，之后只能是小写字母、数字、连字符。
- 由插件自己起名，**与 entry id 无关**。Host 半与浏览器半各自拼同一个字符串，是两边唯一的约定。
- 非法名字在注册时抛 `TypeError`。

## 浏览器侧：SettingsScope

```ts
const scope = ctx.settingsScope.bind<T>({ namespace })   // 需要 inject: ['settingsScope']
```

`ctx.settingsScope` 由 `@deepseek-ai/dsh-client-ui-settings` 提供。`bind` 的返回值（`SettingsScope<T>`）：

| 成员 | 说明 |
| --- | --- |
| `getSnapshot()` | 当前快照。没有变化时返回同一个引用，可以直接喂给 `useSyncExternalStore` 或快照 store |
| `subscribe(listener)` | 订阅快照替换，返回取消订阅的函数 |
| `set(field, value)` | 写一个字段 |
| `unset(field)` | 清一个字段的用户层覆盖，值回落 |
| `mutate(ops, expectedRevision?)` | 一次提交一组路径操作，`{ op: 'set' \| 'unset', path: string[], value? }` |

快照字段（`SettingsScopeSnapshot<T>`）：

| 字段 | 说明 |
| --- | --- |
| `status` | `'loading'` / `'ready'` / `'unavailable'`。Host 不再服务这个 namespace，或页面不在本机（进程内模式）时是 `'unavailable'` |
| `value` | schema 默认值 → 组合 base → 用户层，三层叠完的结果 |
| `base` | 组合 base 层（通常就是 `cordis.yml` 里那一行的 `config`） |
| `user` | 用户层原始内容。**字段出现在这里就算用户覆盖过**，哪怕值与默认相同——判断「改没改过」看键在不在，不要比 value |
| `revision` | 用户层版本号，写的时候回传做并发围栏；首次快照前可能是 `undefined`，可以直接透传 |
| `writable` | 这个部署的设置文档收不收写入 |
| `mode` | `'host'`（写进本机文档）/ `'memory'`（远程页面，进程内，写不进去） |

写入的返回语义：**Host 拒绝写入时 `mutate` / `set` 正常返回，不抛错**；只有传输层异常才 reject。判断有没有落地要读回快照：

```ts
const written = (patch: Record<string, unknown>): boolean => {
    const user = scope.getSnapshot().user as Record<string, unknown> | undefined
    return user !== undefined && Object.keys(patch).every(key => key in user)
}
```

## 浏览器侧：卡片槽位

- 槽位 key：**`settings.plugin.item`**，声明在 `@deepseek-ai/dsh-client-ui-settings-plugins/client`。
- 类型：keyed，`scope: 'root'`，**key = Host 侧注册的 settings namespace**。
- 渲染规则：设置页枚举宿主已服务的 namespace，再与自己这份卡片名单**取交集**；两边都有才渲染。所以「namespace 服务了但没人写卡片」不会自动长出表单，「卡片注册了但 Host 没服务」也不会出现，且都不报错。
- 注册方式：

```ts
ctx.slots.inject('settings.plugin.item', () => ctx.slots.register({
    name: 'settings.plugin.item',
    key: NS,
    inject: () => ({ hooks: { card: store }, save, reset }),
}, Card))
```

- 组件拿不到 `ctx`。`inject` 工厂返回的对象里，`hooks` 这一格是快照源（`getSnapshot` + `subscribe`），会被渲染器绑成 `use<键名首字母大写>` 选择器；其余成员原样作为 props 传进组件。
- 卡片渲染在页签的一个列表里，最外层用 `li`。

## 落盘位置与形状

- 默认路径 `$DSH_HOME/settings.yaml`（`$DSH_HOME` 缺省 `~/.dsh`），由 `@deepseek-ai/dsh-settings-file` 提供；可用插件配置 `path` / `dshHome` 改，支持 `.yaml` / `.yml` / `.json`。
- 顶层键就是 namespace，一段一个 namespace：

```yaml
dsh-chat-background-settings:
  image: /Users/me/wall.png
  opacity: 0.6
```

- 写入是注释保留的叶级差异（`setIn` / `deleteIn`），只动变化的键，同文件其它 namespace 段与外层注释都留着。
- 文档与父目录创建时分别是 `0600` / `0700`；外部手改会被监听并热发布。
- **与 `cordis.patch.yml` 是两份文件。** patch 属于装载层（Loader 读它合成插件行），`settings.yaml` 只覆盖配置的值，不参与装配。因此 `dsh --profile <name> --dump-config` 的输出里看不到设置页写的那层——它只合成 bundle patch、profile patch、home patch 与 `--patch` 覆盖层。

## 两条生效路径对照

| | 改装载层（`cordis.yml` / patch） | 设置页保存 |
| --- | --- | --- |
| 写哪份文件 | 装载层配置文件 | `$DSH_HOME/settings.yaml` |
| 插件是否重启 | 是。这一行的 fiber 被 dispose，`apply` 带新 `config` 重跑 | 否。只换掉这个 namespace 解析出的值 |
| 谁读到新值 | 新一次 `apply` 里的 `config` | 插件下一次调 `source()` |
| 失败时 | 该行回滚到原配置继续跑，告警 + `hmr/config-update-failed` | 拒绝这次写入，文件与运行值都不动 |
| 相关事件 | 配置文件的变化不发 `hmr/change` | 提交后发 `settings/updated` / `settings/document-updated`，并调 `onChange()` |
| `disabled: true` | 释放这一行的 fiber（不是重启），namespace 跟着注销 | — |
